# 存储与恢复

本文说明 PHP Decrypt 0.2 的输出格式、版本记录和故障恢复边界。安装和配置见 [README](../README.md)。

## 目录与版本

所有路径相对于 `decrypt.save_path`：

| 路径 | 作用 |
|---|---|
| `current/<项目相对路径>` | 普通文件最近捕获到的原始字节 |
| `eval/<来源哈希>/<内容哈希>.code` | 按来源和内容区分的字符串编译片段 |
| `objects/<内容哈希前两位>/<内容哈希>.code` | 可选的历史内容对象 |
| `index.jsonl` | 可选的 JSONL 版本记录 |
| `locks/<路径哈希>.lock` | 并发锁和上次成功发布的状态 |

哈希值均为完整 SHA-256。源码与代码片段保留原始字节，`eval/` 内容不自动补充 PHP 起始标签。

同一路径、内容和配置再次出现时，不重复替换文件或追加索引。普通文件从 A 变成 B 再变回 A，开启历史与索引时会记录三次版本变化，但只保存两个内容对象。不同路径的相同内容各有自己的镜像和索引记录，共用历史对象。

`eval/` 按来源和内容保存不同片段，即使 `decrypt.history=0`，不同片段仍会分别保留。关闭 `decrypt.index` 后不再追加版本记录；关闭 `decrypt.history` 后不再写入历史对象。改变配置不会自动清理已有输出。

`current/` 中的文件可能来自不同请求或时间，并非整个项目的事务快照。原项目删除文件不会触发输出清理。捕获运行期间不要删除锁文件或手工修改扩展管理的输出。

## 索引格式

`index.jsonl` 每行一个 JSON 对象，格式版本为 `1`：

| 字段 | 含义 |
|---|---|
| `schema` | 格式版本，目前为 `1` |
| `kind` | `file` 或 `eval` |
| `source_path` | 文件路径或字符串编译器提供的来源标签 |
| `relative_path` | 捕获文件相对于输出根目录的路径，包含 `current/` 或 `eval/` |
| `sha256` | 原始内容的 SHA-256 |
| `bytes` | 原始内容的字节数 |
| `captured_at` | Unix 秒级时间戳 |
| `pid` | 捕获进程号 |
| `object` | 历史对象相对路径，未开启历史时为 `null` |
| `source_path_b64` / `relative_path_b64` | 路径原始字节的 Base64；非 UTF-8 路径以此字段为准 |

索引记录的是已发布的版本变化，而非每一次执行。索引中的相对路径可用于定位镜像或片段，`object` 用于定位对应历史内容。

## 写入与故障恢复

源码先写入目标所在目录的唯一临时文件，完整写入并关闭后再重命名发布。并发更新按路径加锁，索引另行加锁追加；普通捕获不会扫描整个索引。检测到中断的最后一条 JSONL 记录时，会在下次追加前截掉不完整尾行。

发布顺序为历史对象、当前文件、索引、锁文件状态。中途失败不提交成功状态，后续捕获会重试。输出失败会发出警告，通常继续编译原脚本；应用的错误处理器仍可能把警告转换为异常。

临时文件加重命名避免把尚未写完的源码直接发布到目标文件，但不提供跨文件事务。异常中断可能留下临时文件、无索引对象或未索引的当前版本；重试也可能产生重复索引记录。

- `decrypt.sync=0`：默认不进行严格同步，不保证断电后的持久性。
- `decrypt.sync=1`：在 Linux/macOS 上检查文件和目录的 `fsync()` 结果，增加写入延迟；持久性仍取决于文件系统和存储设备。

现有测试未模拟断电，macOS 也未验证 `F_FULLFSYNC`。平台及中断测试的覆盖范围见[运行环境验证](runtime-testing.md)。

## 完整性检查

为减少重复捕获开销，正常捕获信任扩展独占管理的输出和状态，检查存在性、文件类型及大小，不反复读取所有历史对象计算校验和。手工修改或相同长度的数据损坏应通过检查工具识别。

从仓库根目录执行以下命令，路径替换为实际输出目录：

```bash
php tools/verify-captures.php /data/php-captures/shop
```

工具根据索引验证历史对象和每个路径最后记录的捕获文件，检查长度及 SHA-256。它需要可用的 `hash`、`json` 扩展；默认只读，不自动修复。为取得稳定结果，建议暂停捕获后检查。

## 恢复捕获文件

先停用捕获，再执行：

```bash
php tools/verify-captures.php /data/php-captures/shop --repair-current
```

工具验证索引路径和对象校验和，从完整的历史对象恢复索引中最后记录的 `current/` 文件及 `eval/` 片段。恢复结果仍是捕获到的原始字节，不会把包装文件和 eval 片段自动合并为可运行项目。

恢复依赖对应索引记录和完整历史对象，建议保留默认的 `decrypt.history=1`、`decrypt.index=1`。工具拒绝使用损坏对象恢复，不修复历史对象或整个索引，也不会猜测未索引内容。不要仅凭运行成功就认为未被索引引用的文件也已检查。
